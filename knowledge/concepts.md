# FDE 核心概念

## 一句话定义

FDE 深入客户业务现场，把不确定问题转成可运行的生产结果，并把现场经验沉淀为下一次交付可复用的能力。

## FDE 和传统交付的分界

不要只看是否驻场、是否写代码，也不要只看岗位名称。判断一个团队是不是 FDE，可以看项目结束后留下什么：

- 只留下客户定制系统，接近传统外包。
- 团队带回经验，但无法被其他项目直接使用，仍是项目制交付。
- 现场经验进入 Skill、连接器、评测集、模板、本体或产品能力，才形成 FDE 闭环。
- 这些资产在后续项目中缩短周期并降低成本，才具备规模化基础。

## 前线学习

FDE 的核心不是在客户现场待得更久，而是建立更短的学习回路：

`现场问题 -> 可运行验证 -> 生产数据 -> 结构化反馈 -> 平台或知识资产 -> 下一次复用`

交付结果和学习结果缺一不可。只有交付，没有沉淀，团队会逐渐变成人力项目公司。只有抽象，没有生产验证，资产会脱离真实业务。

## 80/95/99

这个框架用来提醒团队区分原型和生产：

- 0 到 80：通用模型和简单流程可以快速覆盖常见路径。
- 80 到 95：需要行业规则、上下文、工具、数据治理和评测。
- 95 到 99：需要长尾样本、权限审计、故障恢复、人工接管和持续运营。

99 不是所有项目的统一目标。高风险场景更重要的是明确自动化边界，让人工守住不适合自动化的部分。

## 本体、Skill 和连接器

- **本体**保存稳定的业务语义，包括对象、属性、关系、动作、状态和规则。
- **Skill**保存完成某类任务所需的判断、步骤、工具和输出要求。
- **连接器**保存系统接入能力，包括鉴权、字段映射、动作接口和异常处理。

三者解决不同问题。不要在高频任务还没有跑通时先建设完整本体，也不要用一堆孤立 Prompt 代替稳定的业务语义。

## 事实边界

本知识库中的报告结论保留页码映射。涉及招聘数量、薪酬、具体产品能力或组织结构时，回答必须提示用户做当前核验。
